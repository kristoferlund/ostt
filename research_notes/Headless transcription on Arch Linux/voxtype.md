# Voxtype: reusable headless transcription versus dictation daemon

## 1. Which project and source version?

### Takeaway
Assuming “Vox type” means **[Voxtype by Peter Jackson / peteonrails](https://github.com/peteonrails/voxtype)**: **partly yes**. It has reusable Rust audio-to-text interfaces, file transcription, and an internal stdin worker; it does **not expose the general resident-model transcription service over HTTP/Unix socket** that “headless engine” might imply. The distinction is supported by the [public transcription module](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs), [CLI](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/cli/commands.rs), and [worker implementation](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/worker.rs).

## 2. What headless/reusable interfaces actually exist?

### Takeaway
**Useful integration components, but not a ready-made, language-neutral resident engine API.** Rust applications can call a real audio-buffer transcription abstraction; other applications can use the WAV CLI or drive microphone dictation, with different limitations. — [Transcriber API](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs#L101-L163); [File command](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/app/transcribe_file.rs)

### Cited Findings
| Surface | Verified behavior and limits | Source |
| --- | --- | --- |
| **Public Rust library** | `pub mod transcribe`; public `Transcriber: Send + Sync`, `transcribe(&self, samples: &[f32]) -> Result<String, …>` for **16 kHz mono f32** audio, `transcribe_timed`, and `create_transcriber(&Config)`. Caller supplies audio; no hotkey/capture/output call is required by this interface. This is genuine code-level reuse, not just dictation controls. | [Exports](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/lib.rs#L71-L106), [Trait/factory](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs#L101-L163) |
| **Rust streaming API** | Public `StreamingTranscriber::start_stream` accepts a Tokio channel of audio buffers; returns partial/final/end/error events and cancellation. Availability depends on backend. This is **in-process**, not a network streaming endpoint. | [Streaming traits/events](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/streaming.rs#L97-L140) |
| **File command** | `voxtype transcribe recording.wav`, independent of the dictation daemon. Uses `hound::WavReader::open(path)`, mixes channels, resamples to 16 kHz, creates a fresh transcriber, prints transcript and exits. **WAV**, not general MP3/Opus decoding. Progress/format messages also use stdout: not a clean text-only/JSON API. | [Implementation](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/app/transcribe_file.rs#L10-L90) |
| **Audio stdin** | No documented `transcribe -` mode: the file command opens a path. However, hidden **`voxtype transcribe-worker`** does read stdin: **u32 little-endian sample count + f32 little-endian samples**, emits `READY`, then JSON `{ok,text,…}` or error, and **exits after one request**. It constructs `WhisperTranscriber` directly: **Whisper-only**, not a provider-neutral worker. Internal GPU-isolation mechanism, not a promised stable public protocol. | [Hidden command](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/cli/commands.rs#L22-L55), [Worker protocol and implementation](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/worker.rs#L1-L16), [Worker lifecycle](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/worker.rs#L63-L182) |
| **Daemon commands / IPC** | `record start/stop/toggle` operate the daemon's **microphone capture**, using SIGUSR1/SIGUSR2 plus runtime override/state files. They do **not submit caller-provided audio**. Integration is richer than hotkeys: `record start --file=out.txt --no-osd`, then `record stop --wait --json` supports external frontends and completion reporting. Still a dictation workflow. | [CLI and completion options](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/cli/record.rs#L14-L118), [Signals/wait implementation](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/app/record.rs#L161-L255) |
| **HTTP / sockets** | Remote Whisper backend is an **HTTP client** to an existing OpenAI-compatible/whisper.cpp server, not a server Voxtype exposes. A real Unix socket, `$XDG_RUNTIME_DIR/voxtype/audio.sock`, broadcasts **waveform-level metrics** to visualizers; it is not audio-input/transcript RPC. No general transcription HTTP/Unix-socket listener found in inspected implementation. | [Remote client](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/remote.rs#L1-L35), [Socket purpose/protocol](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/audio/levels.rs#L1-L22) |
| **Resident model** | Default `[whisper].on_demand_loading = false` preloads and retains the model in the **dictation daemon**. `true` loads on recording and unloads after transcription; GPU isolation intentionally uses one-shot workers. Library `WhisperTranscriber` owns the loaded context, so retaining an instance permits repeated in-process calls. The standalone WAV CLI does not connect to the daemon to reuse its model. | [Configuration](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/docs/CONFIGURATION.md#on_demand_loading), [Owned model context](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/whisper.rs#L17-L44), [Per-call CLI factory](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/app/transcribe_file.rs#L85-L90) |

- **Backends/providers:** source factory includes local Whisper via whisper-rs/whisper.cpp, external `whisper-cli`, remote OpenAI-compatible Whisper, feature-gated ONNX Parakeet/Moonshine/SenseVoice/Paraformer/Dolphin/Omnilingual/Cohere, feature-gated OpenVINO Whisper, and **Soniox cloud**. Soniox supports WebSocket realtime and asynchronous upload/poll APIs. Do not mistake comments listing Gemini/OpenAI Realtime/ElevenLabs as implemented providers. — [Actual factory](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs#L162-L325); [Whisper backend selection](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs#L395-L451); [Soniox documentation](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/docs/SONIOX.md)
- **Modularity caveat:** public engine APIs live inside the main `voxtype` package, which also exports desktop/audio/daemon/TUI functionality. This is not a separately packaged lean engine crate in the inspected workspace. README engine counts and “no cloud” wording are less complete than the current factory/configuration; prefer implementation for availability. — [Library](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/lib.rs); [Package/workspace/dependencies](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/Cargo.toml); [Factory](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs)

### Inferences
- **Custom frontend controlling Voxtype's microphone recorder:** practical existing fit; use `record … --file`, `--no-osd`, completion JSON. **Independent app supplying arbitrary audio to one warm shared engine:** needs an adapter/service or in-process Rust integration; the daemon commands alone do not provide that. — [Record interface](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/cli/record.rs); [Transcriber interface](https://github.com/peteonrails/voxtype/blob/dc499ad47444ba6ea80d8750aa3581c23120821c/src/transcribe/mod.rs#L101-L163)

### Gaps
- No documented compatibility guarantee for external use of the hidden worker, nor a separately verified stable SDK contract.
- Did not test server-only builds or quantify desktop dependency overhead for library consumers.
