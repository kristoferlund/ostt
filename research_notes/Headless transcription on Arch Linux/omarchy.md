# Omarchy: official dictation, headless transcription, and community adoption

Research cutoff/access date: **2026-10-21**. Primary evidence: GitHub API, tagged source, release notes, official manuals, upstream tool documentation. `basecamp/omarchy` now redirects to `omacom/omarchy`; its default branch is `quattro`. [Repository metadata](https://api.github.com/repos/basecamp/omarchy)

## What has officially shipped, versus merged or proposed integration?

### Takeaway
**Stable Omarchy ships opt-in Voxtype integration, not an installed-by-default speech engine. Superwhisper cloud dictation as the fresh-install default is merged and included in 4.5.0-rc1, but is not in the latest stable 4.0.6.** The live website manual describes the newer behavior; do not apply it indiscriminately to stable installations. [Stable release](https://github.com/omacom/omarchy/releases/tag/v4.0.6), [RC release](https://github.com/omacom/omarchy/releases/tag/v4.5.0-rc1), [stable manual source](https://github.com/omacom/omarchy/blob/v4.0.6/manual/11-text-extraction-dictation.md), [live manual](https://omarchy.org/manual/text-extraction-dictation/)

### Cited Findings
- **2026-01-07 — stable 3.3.0:** release notes explicitly introduce “opt-in dictation via Voxtype” through **Install > AI > Dictation**, credited to DHH. Installer selects a roughly 150 MB English model; users can change models/settings. This is official integration, not merely a community workaround. [Release](https://github.com/omacom/omarchy/releases/tag/v3.3.0)
- **2026-02-26 — 3.4.0:** DHH changed `Super + Ctrl + X` from hold-to-talk to toggle because of Hyprland key-release complications. **2026-04-23 — 3.6.0:** release notes add GPU migration, media pausing, and a status-process fix. **2026-05-09 — 3.8.0:** adds an *offer* to install Voxtype after a fresh installation's first update—not unconditional installation. [3.4.0](https://github.com/omacom/omarchy/releases/tag/v3.4.0), [3.6.0](https://github.com/omacom/omarchy/releases/tag/v3.6.0), [3.8.0](https://github.com/omacom/omarchy/releases/tag/v3.8.0)
- **Latest stable, 4.0.6, published 2026-10-19:** its manual still directs users to **Install > AI > Dictation**. Its installer prompts, installs `wtype voxtype-bin`, copies config, downloads the model, attempts Vulkan setup when detected, and configures systemd. Its ISO base package list contains neither Voxtype nor Superwhisper. F9 hold and `Super + Ctrl + X` toggle are registered only when `voxtype` is present. [Release](https://github.com/omacom/omarchy/releases/tag/v4.0.6), [installer](https://github.com/omacom/omarchy/blob/v4.0.6/bin/omarchy-voxtype-install), [base packages](https://github.com/omacom/omarchy/blob/v4.0.6/install/omarchy-base.packages), [bindings](https://github.com/omacom/omarchy/blob/v4.0.6/default/hypr/bindings/voxtype.lua)
- **2026-10-08 — merged upstream:** DHH's **#14552**, “Add selectable Voxtype and Superwhisper dictation,” merged at 18:37 UTC. Adds **Setup > Defaults > Dictation**, a saved provider choice, shared recording commands/shortcuts, provider adapters, and third-party extension protocol. Existing Voxtype users are preserved by a migration. [PR](https://github.com/omacom/omarchy/pull/14552)
- **2026-10-08 — merged default change:** DHH's **#14625**, merged 19:23 UTC, adds `superwhisper-bin` to the ISO package list and `superwhisper` to the shipped selection file, relying on vendor cloud-processing defaults without offline-model downloads; existing backend choices remain unchanged. Companion package **omarchy-pkgs#854** merged the same day and packages the vendor's signed binary, CLI, service and desktop integration through pacman/OPR. [Default PR](https://github.com/omacom/omarchy/pull/14625), [package PR](https://github.com/omacom/omarchy-pkgs/pull/854)
- **2026-10-20 — 4.5.0-rc1:** release explicitly warns it is a release candidate and lists Superwhisper/Voxtype support. Its tagged ISO package list includes `superwhisper-bin`, and tagged default selection is `superwhisper`. Thus this is **released in an RC**, not just an unmerged plan, but not stable yet. [RC notes](https://github.com/omacom/omarchy/releases/tag/v4.5.0-rc1), [RC packages](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/install/omarchy-base.packages), [RC selection](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/config/omarchy/defaults/dictation)
- **RC/new workflow configuration:** holding Right Alt/F9 or toggling `Super + Ctrl + X` invokes the selected provider. Choosing Voxtype installs/configures it if needed; model defaults remain `base.en`, language `en`, local inference and typed output. Model/language/device/output changes are **user configuration**, not an Omarchy-developed model. Superwhisper settings offer cloud/local processing. [Manual](https://omarchy.org/manual/text-extraction-dictation/), [RC Voxtype config](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/default/voxtype/config.toml)
- **Open proposals as of cutoff—not shipped:** draft **#13098** (opened Sep 24) proposes verified local Cohere/Vulkan defaults, paste output and new visuals; draft **#5177** (opened Apr 1) proposes Intel NPU/OpenVINO support; **#15282** (opened Oct 13) proposes F10 transcription of speaker/monitor audio; **#9320** (opened Aug 31) proposes optional Oma voice-to-desktop actions using a separate daemon and paid API. All were open with `merged_at: null` when checked. [#13098](https://github.com/omacom/omarchy/pull/13098), [#5177](https://github.com/omacom/omarchy/pull/5177), [#15282](https://github.com/omacom/omarchy/pull/15282), [#9320](https://github.com/omacom/omarchy/pull/9320)
- **Closed ≠ merged:** the hyprwhspr integration request **#2467** opened Oct 15, 2025 and closed Jan 6, 2026; it was an issue requesting team feedback before a PR, not evidence of a shipped integration. Similarly Superwhisper proposal **#14620** closed without merging; use merged #14552/#14625 for actual implementation. [Issue](https://github.com/omacom/omarchy/issues/2467), [unmerged PR](https://github.com/omacom/omarchy/pull/14620)

### Inferences
- Stable 4.0.6 and the current web manual conflict because they describe different development/release states. Prefer **tagged stable source for stable claims** and explicitly label RC/mainline behavior. [Stable source](https://github.com/omacom/omarchy/blob/v4.0.6/manual/11-text-extraction-dictation.md), [current manual](https://omarchy.org/manual/text-extraction-dictation/)

### Gaps
- Source/release inspection is not a fresh ISO/VM installation test. DHH's October default-install PR itself says no audio was recorded and no fresh ISO/VM install was run; an open Oct 15 report concerns missing Superwhisper per-user setup. ## Does Omarchy develop an engine, and what is actually headless?

### Takeaway
The evidenced Omarchy work is **integration/packaging/orchestration of external transcription tools**, not development of its own recognition engine. Voxtype provides a genuine daemonless file-transcription CLI upstream; Omarchy's default workflow remains microphone-to-focused-desktop-input dictation. [Stable installer](https://github.com/omacom/omarchy/blob/v4.0.6/bin/omarchy-voxtype-install), [RC adapter](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/bin/omarchy-dictation-voxtype), [Voxtype CLI](https://voxtype.io/docs/USER_MANUAL#voxtype-transcribe-file)

### Cited Findings
- Voxtype is separately developed in **peteonrails/voxtype**; its manual says Whisper runs through **whisper.cpp**, with additional engines available upstream. Omarchy's checked-in default chooses Whisper `base.en`, not every engine the latest Voxtype supports. [Repository](https://github.com/peteonrails/voxtype), [engine documentation](https://voxtype.io/docs/USER_MANUAL#transcription-engines), [Omarchy config](https://github.com/omacom/omarchy/blob/v4.0.6/default/voxtype/config.toml)
- Upstream documents `voxtype transcribe recording.wav` as **“Transcribe an audio file without running the daemon”**, recommending 16-bit PCM/16 kHz mono WAV. It also documents `voxtype record start --file=out.txt` to write live-recording transcription to a file instead of keyboard/clipboard output. These are upstream capabilities, **not a separate Omarchy transcription service shipped by default**. [File transcription](https://voxtype.io/docs/USER_MANUAL#voxtype-transcribe-file), [record/file output](https://voxtype.io/docs/USER_MANUAL#voxtype-record)
- The newer `omarchy dictation start|stop|toggle` interface delegates to provider commands; the Voxtype adapter invokes `voxtype record`, and the Superwhisper adapter invokes `superwhisper start|stop|record`. Additional providers can supply an `omarchy-dictation-<backend>` adapter and installer. This is desktop integration extensibility, not a new ASR implementation. [Dispatcher](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/bin/omarchy-dictation), [Voxtype adapter](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/bin/omarchy-dictation-voxtype), [Superwhisper adapter](https://github.com/omacom/omarchy/blob/v4.5.0-rc1/bin/omarchy-dictation-superwhisper), [protocol manual](https://omarchy.org/manual/text-extraction-dictation/)
- **Handy** is a separate offline speech-to-text application. Its current README distinguishes CLI *remote-control flags for an already-running instance* (`--toggle-transcription`, `--cancel`) from hidden startup (`--start-hidden --no-tray`); those flags alone do not demonstrate a display-independent batch engine. [Handy CLI documentation](https://github.com/cjpais/Handy#cli-parameters)

### Inferences
- For “headless” meaning **no app window while dictating**, daemon/CLI workflows fit. For **no graphical session, automated audio-file processing**, distinguish Voxtype's explicit file command from Omarchy's keyboard/clipboard desktop plumbing; do not call the whole desktop integration headless merely because its control surface is shell commands. [Voxtype file command](https://voxtype.io/docs/USER_MANUAL#voxtype-transcribe-file), [Omarchy workflow](https://github.com/omacom/omarchy/blob/v4.0.6/manual/11-text-extraction-dictation.md)

### Gaps
- No official Handy integration, Omarchy-owned ASR model/engine, or dedicated official headless batch-transcription service was found in the inspected tree, releases and issue/PR searches. This is a bounded search result, not proof that no discussion/experiment exists. [Tree queried](https://api.github.com/repos/omacom/omarchy/git/trees/quattro?recursive=1), [Handy issue/PR search](https://github.com/omacom/omarchy/issues?q=Handy), [releases](https://github.com/omacom/omarchy/releases)
- No no-display runtime tests or packaged-Voxtype-version capability tests were performed; upstream live documentation may describe newer features than any particular installed package. [Upstream manual](https://voxtype.io/docs/USER_MANUAL)

## What do maintainers and community evidence actually establish?

### Takeaway
There is credible evidence of **real users, upstream collaboration and sustained official integration**, but not a measured mass-adoption rate among Omarchy users. Third-party projects named for Omarchy are not automatically official features. [DHH statement](https://github.com/omacom/omarchy/issues/1991), [upstream collaboration](https://github.com/omacom/omarchy/issues/4159), [official initial release](https://github.com/omacom/omarchy/releases/tag/v3.3.0)

### Cited Findings
- **DHH, 2026-02-20:** “We now have voxtype built in,” on an earlier dictation proposal. Interpret “built in” as official support: the contemporary 3.3.0 notes explicitly call installation **opt-in**. [Statement](https://github.com/omacom/omarchy/pull/1991#issuecomment-3935637260), [release wording](https://github.com/omacom/omarchy/releases/tag/v3.3.0)
- **Voxtype maintainer peteonrails, Jan 9–10, 2026:** accepted an upstream modifier-key bug and discussed output hooks; wrote, “One of the reasons I didn't discover this bug until Omarchy users started using Voxtype…” This directly supports actual Omarchy use and upstream collaboration, not a user count. DHH closed the issue July 18 as superseded by Quattro/consolidated issues/retired configuration, so old search snippets labeling it open are stale. [Issue and dated comments](https://github.com/omacom/omarchy/issues/4159)
- **hyprwhspr** is a separate goodroot project, promoted in Omarchy's **Show and tell** discussion on Aug 28, 2025. Discussion contains installation/microphone troubleshooting and a Jan 10, 2026 thank-you—not evidence of default installation or widespread adoption. Its explicit integration request was closed, not merged. [Discussion #1258](https://github.com/omacom/omarchy/discussions/1258), [request #2467](https://github.com/omacom/omarchy/issues/2467), [project](https://github.com/goodroot/hyprwhspr)
- **michabbb/omarchy-speech-to-text** supplies Faster Whisper/Python recording and ydotool/systemd setup. Its author explicitly calls it AI-assisted, says they are not a Python developer, and frames it as “here’s how it can work,” not guaranteed turnkey software. **robzolkos/shout** is another separate Wayland/Hyprland whisper-based tool requiring the user's own keybinding. These are community alternatives, not Omarchy-owned engines. [First project README](https://github.com/michabbb/omarchy-speech-to-text), [Shout README](https://github.com/robzolkos/shout)
- **GitHub interest snapshot, retrieved Oct 21, 2026:** Voxtype **1,673 stars / 184 forks**; hyprwhspr **1,256 / 106**; michabbb's Omarchy-specific project **28 / 1**; Shout **70 / 7**. These establish varying project interest only—neither installed-user counts nor Omarchy-specific adoption. Handy's **34,261 stars / 3,254 forks** are cross-platform project interest, not evidence Omarchy ships/uses it. [Voxtype API](https://api.github.com/repos/peteonrails/voxtype), [hyprwhspr API](https://api.github.com/repos/goodroot/hyprwhspr), [Omarchy-specific API](https://api.github.com/repos/michabbb/omarchy-speech-to-text), [Shout API](https://api.github.com/repos/robzolkos/shout), [Handy API](https://api.github.com/repos/cjpais/Handy)

### Inferences
- The strongest defensible adoption wording is **“officially integrated since January 2026, with documented user feedback and upstream fixes; multiple community alternatives also exist.”** Do not write “most Omarchy users,” “mass adoption,” or infer active users from stars. [Release](https://github.com/omacom/omarchy/releases/tag/v3.3.0), [user/upstream feedback](https://github.com/omacom/omarchy/issues/4159)

### Gaps
- No representative survey, dictation install telemetry, active-user total or Omarchy-specific market-share measurement was located. Repository metrics and discussion samples cannot answer prevalence. [Repository metrics](https://api.github.com/repos/peteonrails/voxtype), [sample discussion](https://github.com/omacom/omarchy/discussions/1258)
- Firecrawl scraping worked; its search endpoint failed with an API-access error, so discovery used the available web search plus GitHub APIs. Dates/statuses above were checked against live primary sources rather than trusting search snippets.
